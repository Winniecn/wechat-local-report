# 本机读取路径与兼容边界

## 读取前检查

项目默认 `~/Documents/WeChatgroup`，运行时使用项目 `.venv/bin/python`；helper 可 `--project /绝对路径`。读取项目 README 当前结论、`wechat_report/debug_copy.py` 和必要的局部规范。缺项目或依赖不全时先修复项目级依赖，不能仅安装这个 Skill 就声称引擎已安装。

需要 Python3.10+（本机3.12）、系统LLDB、项目锁定依赖和Chrome。重建项目虚拟环境时使用 requirements.lock.txt，勿安装全局依赖。`doctor` 只读探测，历史兼容信息不代表本次已经取到密钥。

实测：macOS26.5.1、arm64、App Store微信4.1.13（269602）。其他客户端版本和系统组合未验证。读取前核对当前版本；版本不同停止沿用签名流程，不能移除版本限制或自动降级/升级微信。账号从 doctor 与实际登录界面确认，不在 Skill 保存账号或群ID。

## 授权边界

本任务如已有用户针对同版本临时副本调试及重新登录的明确授权，继续复用，不重复询问。新会话没有这项授权时，先完成只读检查并说明：会短暂退出微信，使用保留 App Sandbox 的同版本临时副本，放宽该副本的调试及部分运行时校验；原版不修改，可能需手机确认，之后恢复原版。此具体动作获授权后再执行；普通“总结群聊”不能自行扩大成修改系统安全设置。

密钥不写入参数、环境变量、日志、配置或报告，不让用户粘贴。不要打印调试器原始输出。只使用引擎私有管道。数据读取源库只读；客户端登录本身仍有正常同步写入。只能保证尽可能清理可控临时文件，不能承诺断电、SIGKILL或文件系统快照中的安全擦除。

## 已验证流程

1. 正常退出原版程序，不退出账号，不删除数据。用微信菜单“退出微信”；普通快捷键可能仅显示长按提示。工具超时不等于退出失败，用进程/界面确认。不要 killall 或影响其他账号/副本。
2. 默认副本路径 `/private/tmp/wechat-report-account-probe/WeChat.app`。已有时用项目 `debug_copy.verify_copy` 校验清单、身份、权限与哈希。沙箱的签名信任服务错误先在正常权限环境中复核，不直接改签名“修复”。
3. 不存在时，在已授权范围内使用：

```sh
cd <project>
.venv/bin/python scripts/prepare_debug_copy.py /private/tmp/wechat-report-account-probe/WeChat.app
```

目标存在但校验失败，先诊断，不覆盖或删除。必要时用另一个未使用的 `/private/tmp/wechat-report-*` 目录，并将 `--debug-app` 指向它。

4. helper plan 生成 `--capture-key --capture-timeout 600 --launch-debug-app --debug-app ...` 的冻结时间导出命令。启动前须没有其他微信主进程。捕获方式固定已验证 pbkdf 系统符号路径，非猜测版本偏移。
5. 从调试器启动后若有临时路径提示，关闭提示，不更改永久设置。只在真实 CAPTURE_READY 后点击登录。自动登录时无需点击；手机确认必须由本人完成。
6. 群精确匹配失败且提供 keyword 时，只列候选名称/ID。唯一明确对应可选择；同名结合元信息仍不确定，问用户。选择时写入该运行会话 stdin，不能读取其他群来猜。
7. 同步中的快照重试由引擎执行（最多约1分钟）。超时或校验失败应停止；不要删原WAL、跳过HMAC或放宽schema检查。
8. 导出退出后确认临时快照清理，再正常退出已确认的临时副本，重新打开原版并核对界面。如恢复登录需手机操作，清楚告知，不把登录页称为主界面。

## 不再重复的历史路径

- 原版 sudo LLDB：本机已验证系统仍拒绝附加。
- 删除所有 entitlement 或取消沙盒：不属于本流程。
- WorkBuddy取密钥脚本：含密钥持久化及其他回退行为，不能直接运行。
- raw-key内存字符串扫描：本机未成功验证，不作为失败后的默认回退。
- 把签名检查通过、出现扫码页、取得候选密钥，任何单一步骤当作完整读取成功。
